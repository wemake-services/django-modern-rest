# Upgrade django-modern-rest from 0.15.0 to 0.16.0

Source: `CHANGELOG.md`, release `0.16.0`.
Breaking changes for this release are listed in `CHANGELOG.md` under `0.16.0`.

Read this file only while upgrading across this release. Apply every item,
search the whole project (including tests and fixtures) for each one.

## Prompt

You are migrating a Python project from `django-modern-rest` 0.15.0 to 0.16.0.
Load the documentation for the installed version, `llms.txt` lists every page:
https://django-modern-rest.readthedocs.io/en/latest/llms.txt

Apply **all** of the following breaking changes to the codebase.
For each change, search the entire project (including tests, fixtures, and
any helper modules) before editing.

---

### `Controller.as_view()` raises for abstract controllers

`Controller.as_view` now raises `EndpointMetadataError` when the controller
is abstract: it has no exact serializer type (for example, a generic base
class still parametrized with a type var) or it has no endpoints.
Such controllers used to be added to `Router` and `urlpatterns` silently
and then failed on every request.

Find every `.as_view()` call and every `Router` / `path()` entry that
points at a base or mixin controller and remove it from routing.
Keep the class as a base class only, route its concrete subclasses.

---

### `Controller.login_required` defaults to `False`

`Controller` now sets `login_required = False` on every view it builds,
which exempts all controllers from Django's `LoginRequiredMiddleware`.
Projects that relied on that middleware to protect API endpoints
are now open.

Check whether `django.contrib.auth.middleware.LoginRequiredMiddleware`
is in `MIDDLEWARE`. If it was guarding API endpoints, configure
authentication in `django-modern-rest` instead (`auth=` on endpoints,
controllers, or `Settings.auth`), or set `login_required = True`
on the controllers that must stay behind the middleware.

---

### Configuration levels are not merged anymore

`auth`, `throttling`, `parsers`, `renderers`, `responses`, `tags`,
`exclude_validate_responses`, `exclude_semantic_responses`,
and `no_validate_http_spec` used to be merged from settings, router,
controller, and endpoint levels. Now the first explicitly defined level wins:
endpoint values override controller values, controller values override
settings values (and router values for `tags`).

Explicit empty values like `auth=[]` or `throttling=()` are taken literally
as "nothing on this level", exactly like `None`, they do not fall through
to the next level anymore. Only `EMPTY` (or not setting the value at all)
uses the next level.

Find every endpoint and controller that sets one of these values
while expecting the controller or settings values to still apply:

- Where the old merged result is wanted, merge explicitly:

      @modify(auth=[*ControllerClass.auth, OtherAuth()])
      @modify(responses=[*base_responses, ResponseSpec(...)])

- Where `[]`, `()`, or `None` was passed to "add nothing",
  remove the argument so the next level is used.

- Where a whole project relied on merging, subclass
  `dmr.validation.MetadataMerger` and set `Endpoint.metadata_merger_cls`
  (through a custom endpoint class) instead of rewriting every endpoint.

---

### Endpoint, controller, and settings values default to `EMPTY`

All endpoint, controller, and settings values now default to `EMPTY`
("not set on this level") instead of `None`. `None` is only allowed where
it disables something explicitly, like `auth=None`.
This affects `validate_responses`, `semantic_responses`, `validate_events`,
`validate_negotiation`, `ignore_from_spec`, `error_handler`, `status_code`,
`headers`, `cookies`, `operation_id`, `external_docs`, `callbacks`,
`servers`, `links`, `response_description`,
and `Settings.openapi_examples_seed`.

Find every explicit `None` passed to these values in `@modify`, `@validate`,
controller class attributes, and `Settings` that meant "use the next level"
and remove it. Keep `None` only where it must disable the value.
Custom code that inspects controller attributes or metadata for `None`
as "unset" must compare against `EMPTY` from `dmr.types` instead:

Before:
    class MyController(Controller[Serializer]):
        semantic_responses = None  # meant: use the settings one
        renrederes = ()  # meant: use the settings one

After:
    class MyController(Controller[Serializer]):
        pass  # EMPTY by default, the settings value is used

---

### `Router.deprecated` is the last level, not `OR`

`deprecated` is resolved like `tags`: the first explicitly defined level
wins, from endpoint to controller to router. `@modify(deprecated=False)`
or `Controller.deprecated = False` now un-deprecates an operation
inside `Router(deprecated=True)`, it used to stay deprecated.
`deprecated` of `@modify` and `@validate` defaults to `EMPTY`,
and `EndpointMetadata.deprecated` can be `EMPTY` too.

Find `deprecated=False` on endpoints under deprecated routers
and remove it to keep them deprecated.

---

### `Controller.servers` is resolved per operation

`Controller.servers` defaults to `EMPTY` and is resolved into
`EndpointMetadata.servers` of every endpoint, the first explicitly defined
level wins. Servers are dumped on each operation instead of the path item.
The effective servers of every operation stay the same,
but `servers=None` on an endpoint now disables the controller value.

Regenerate OpenAPI snapshot tests. Find code that reads
`path_item.servers` from generated schemas and read `operation.servers`.
Find `@modify(servers=None)` that meant "inherit" and remove the argument.

---

### `summary` and `description` are resolved one at a time

`@modify(...)` and `@validate(...)` now resolve `summary` and `description`
independently. Passing one of them no longer drops the docstring for the other.
Both default to `EMPTY` instead of `None`, so an explicit `None`
now means "generate nothing", not "use the docstring".

Find every `@modify` / `@validate` (and `.lazy` variants, and `modify_spec`
of shipped views) that passes `summary=None` or `description=None`
to mean "take it from the docstring" and remove that argument.
Keep `None` only where the intent is to produce no text at all.

---

### Removed `throttling_allow_unsafe_cache`

`Settings.throttling_allow_unsafe_cache`, the `throttling_allow_unsafe_cache`
controller attribute, the `@modify` / `@validate` parameter,
and `EndpointMetadata.throttling_allow_unsafe_cache` are gone.
The check now belongs to the cache backend:
`SyncDjangoCache(allow_unsafe_cache=...)` and
`AsyncDjangoCache(allow_unsafe_cache=...)`.

Type `bool | None` stayed the same, but value meanings did change:

- `None` (default) emits `UnsafeCacheBackendWarning` only when
  `settings.DEBUG` is `False`,
- `True` disables the check completely,
- `False` raises `EndpointMetadataError`.

Find every `throttling_allow_unsafe_cache` in settings, controllers,
endpoints, and tests, remove it, and pass the value to the backend instance:

Before:
    DMR_SETTINGS = {Settings.throttling_allow_unsafe_cache: False}

    class MyController(Controller[Serializer]):
        throttling_allow_unsafe_cache = True

After:
    SyncDjangoCache(allow_unsafe_cache=False)
    SyncDjangoCache(allow_unsafe_cache=True)

---

### `validate_events` moved to `Streaming` extras

The `validate_events` parameter was removed from `@modify` and `@validate`,
and `Controller.validate_events` was removed as well.
It was silently ignored for non-streaming controllers.
Use `extras=Streaming(validate_events=...)` with `dmr.streaming.modify`
and `dmr.streaming.validate`, or `extras = Streaming(validate_events=...)`
on streaming controllers.

Before:
    from dmr.endpoint import modify

    class Events(SSEController[Serializer]):
        validate_events = False

        @modify(validate_events=True)
        async def get(self) -> AsyncIterator[SSEvent[int]]: ...

After:
    from dmr.streaming import Streaming, modify

    class Events(SSEController[Serializer]):
        extras = Streaming(validate_events=False)

        @modify(extras=Streaming(validate_events=True))
        async def get(self) -> AsyncIterator[SSEvent[int]]: ...

Remove `validate_events` from non-streaming controllers and endpoints,
it had no effect. `Settings.validate_events` still exists.

---

### `StreamingController.streaming_ping_seconds` moved to `Streaming` extras

`StreamingController.streaming_ping_seconds` was removed.
Use `extras = Streaming(ping_seconds=...)` on streaming controllers
or `extras=Streaming(ping_seconds=...)` per endpoint
with `dmr.streaming.modify` / `dmr.streaming.validate`.
`SSEController` still sends pings every 15 seconds by default.

Before:
    class Events(SSEController[Serializer]):
        streaming_ping_seconds = 30

After:
    from dmr.streaming import Streaming

    class Events(SSEController[Serializer]):
        extras = Streaming(ping_seconds=30)

When both `validate_events` and `ping_seconds` are set on one controller
or endpoint, pass them to a single `Streaming(...)`.

After:

### `secure` and `httponly` cookie flags can no longer be `None`

`NewCookie.secure`, `NewCookie.httponly`, `CookieSpec.secure`,
and `CookieSpec.httponly` must be `bool`. Replace every explicit `None`
with `False`.

Before:
    NewCookie('session', 'abc', secure=None, httponly=None)

After:
    NewCookie('session', 'abc', secure=False, httponly=False)

### `Endpoint` objects are not callable

Find every place that calls an `Endpoint` instance directly
(custom controllers, middleware, tests calling `controller.api_endpoints[...]`)
and call its `.func` attribute instead:

Before:
    endpoint(controller, ...)

After:
    endpoint.func(controller, ...)

### `ComponentParserSpec` moved and grew a `default` field

`ComponentParserSpec` now lives in `dmr.components` and is a named tuple
of `parser`, `model`, `model_meta`, and `default`.
It used to be a plain tuple of three elements in `dmr.metadata`.

Find every import of `ComponentParserSpec` from `dmr.metadata` and every
three-way unpacking of `metadata.component_parsers` items.

Before:
    from dmr.metadata import ComponentParserSpec

    for component, model, meta in metadata.component_parsers:
        ...

After:
    from dmr.components import ComponentParserSpec

    for spec in metadata.component_parsers:
        spec.parser, spec.model, spec.model_meta, spec.default

### Custom serializers must implement `build_context_model`

`BaseSerializer.build_context_model(name, fields)` is a new abstract
class method. It receives a mapping of field names
to `dmr.serializer.ContextField` objects (annotation and default)
and returns `dmr.serializer.ContextModel` (model and an optional
`to_kwargs` converter).

Find every `BaseSerializer` subclass that is not a subclass of the bundled
`PydanticSerializer` or `MsgspecSerializer` and implement the method.
The simplest implementation builds a `TypedDict` with `total=True`
and returns `ContextModel(model)`, but it cannot support defaults.

---

### `BaseSerializer.is_supported` is replaced with `BaseSerializer.validate`

`is_supported(pluggable)` returned a `bool` for a single parser or renderer.
It is replaced with the class method
`validate(controller_cls, metadata)` that receives the complete
`EndpointMetadata` and raises `EndpointMetadataError` instead.
It runs last in the endpoint validation, so it can check
parsers, renderers, components, and everything else at once.
The default implementation accepts every endpoint.

Find every `is_supported` override and every direct call in tests:

Before:
    @classmethod
    def is_supported(cls, pluggable: Parser | Renderer) -> bool:
        return isinstance(pluggable, MyParser)

After:
    @classmethod
    def validate(
        cls,
        controller_cls: type[Controller[BaseSerializer]],
        metadata: EndpointMetadata,
    ) -> None:
        for parser in metadata.parsers:
            if not isinstance(parser, MyParser):
                raise EndpointMetadataError(...)

---

### Component annotations hidden inside other types are rejected

Things like `parsed_body: Body[Model] | None = None` used to be silently
ignored, since the component is hidden behind a union.
Now they raise `UnsolvableAnnotationsError` at import time.
The optional part must go inside the component.

Find every endpoint parameter whose annotation wraps `Body`, `Query`,
`Headers`, `Cookies`, `Path`, or a custom component in `Optional`,
a union, or any other outer type:

Before:
    def post(self, parsed_body: Body[Model] | None = None) -> Model: ...

After:
    def post(self, parsed_body: Body[Model | None] = None) -> Model: ...

### Custom components receive `default`, `metadata`, and `controller_cls`

- `ComponentParser.provide_context_data` now accepts a keyword-only
  `default` parameter, custom components must accept it as well.
  It is the default value of the endpoint parameter or `EMPTY`
  when there's none. When it is not `EMPTY` and the request carries
  no data for the component, return `default` as-is.
- `ComponentParser.get_schema` accepts `controller_cls`
  instead of `serializer`.
- `SupportsFileParsing.schema_metadata` accepts `controller_cls`
  instead of `serializer`.
- `FileBodyLike.media_type` now also accepts `metadata` and `controller_cls`
  and gets a `Schema` instead of `Reference | Schema`.

Find every subclass of `ComponentParser`, `SupportsFileParsing`,
and `FileBodyLike` and update the signatures:

Before:
    def provide_context_data(
        self,
        endpoint: Endpoint,
        controller: Controller[BaseSerializer],
        *,
        field_model: Any,
    ) -> Any | tuple[Any, ...]: ...

    def get_schema(
        self,
        model: Any,
        model_meta: tuple[Any, ...],
        metadata: EndpointMetadata,
        serializer: type[BaseSerializer],
        context: OpenAPIContext,
    ) -> list[Parameter | Reference] | RequestBody: ...

    def schema_metadata(
        self,
        model: Any,
        model_meta: tuple[Any, ...],
        metadata: EndpointMetadata,
        serializer: type[BaseSerializer],
        context: OpenAPIContext,
    ) -> type[FileBodyLike]: ...

    @classmethod
    def media_type(
        cls,
        schema: Reference | Schema,
        model: Any,
        model_meta: tuple[Any, ...],
        parser: Parser,
        context: OpenAPIContext,
    ) -> MediaType: ...

After:
    def provide_context_data(
        self,
        endpoint: Endpoint,
        controller: Controller[BaseSerializer],
        *,
        field_model: Any,
        default: Any = EMPTY,
    ) -> Any | tuple[Any, ...]: ...

    def get_schema(
        self,
        model: Any,
        model_meta: tuple[Any, ...],
        metadata: EndpointMetadata,
        controller_cls: type[Controller[BaseSerializer]],
        context: OpenAPIContext,
    ) -> list[Parameter | Reference] | RequestBody: ...

    def schema_metadata(
        self,
        model: Any,
        model_meta: tuple[Any, ...],
        metadata: EndpointMetadata,
        controller_cls: type[Controller[BaseSerializer]],
        context: OpenAPIContext,
    ) -> type[FileBodyLike]: ...

    @classmethod
    def media_type(
        cls,
        schema: Schema,
        model: Any,
        model_meta: tuple[Any, ...],
        metadata: EndpointMetadata,
        controller_cls: type[Controller[BaseSerializer]],
        parser: Parser,
        context: OpenAPIContext,
    ) -> MediaType: ...

Use `controller_cls.serializer` where `serializer` was used before.

### `MsgspecJsonParser.strict` and `MsgpackParser.strict` default to `False`

Both used to default to `True`. They only affect `BodyMsgspec`,
and lax mode matches how regular request bodies are validated.

If the project relies on strict decoding of `BodyMsgspec`,
subclass the parser and keep the old value:

    from typing import ClassVar

    from dmr.plugins.msgspec import MsgspecJsonParser

    class StrictJsonParser(MsgspecJsonParser):
        strict: ClassVar[bool] = True

and use it in `parsers=` where needed.

### Auth classes: `security_schemes` and `security_requirements` are methods

For every custom auth class (subclasses of `SyncAuth`, `AsyncAuth`,
and of the shipped token / JWT / session auth classes) rewrite:

- the `security_schemes` property into a method
  `security_schemes(self, metadata, controller_cls)`,
- the `security_requirement` property into a method named
  `security_requirements(self, metadata, controller_cls)`
  that returns a `list[SecurityRequirement]`
  (it can now express both `AND` and `OR` strategies).

Before:
    @property
    def security_schemes(self) -> dict[str, SecurityScheme | Reference]:
        return {self.security_scheme_name: SecurityScheme(...)}

    @property
    def security_requirement(self) -> SecurityRequirement:
        return {self.security_scheme_name: []}

After:
    def security_schemes(
        self,
        metadata: EndpointMetadata,
        controller_cls: type[Controller[BaseSerializer]],
    ) -> dict[str, SecurityScheme | Reference]:
        return {self.security_scheme_name: SecurityScheme(...)}

    def security_requirements(
        self,
        metadata: EndpointMetadata,
        controller_cls: type[Controller[BaseSerializer]],
    ) -> list[SecurityRequirement]:
        return [{self.security_scheme_name: []}]

Update every direct call of these members in tests.

### `SyncOrAsyncAuth.resolve` and `SyncOrAsyncThrottle.resolve` take `is_async`

Before:
    auth.resolve(auth_cls=SyncAuth)

### Removed `jwt_ensure_csrf` from JWT cookie views

`jwt_ensure_csrf` was removed from the reusable JWT cookie controllers
(`CookieObtainTokens*`, `CookieRefreshTokens*`, `CookieLogout*`),
CSRF protection is now always mandatory for them.

Find every `jwt_ensure_csrf = False` and remove it.
Make sure clients of these views send the CSRF token

### Cookie JWT auth uses `jwt_cookie` as the security scheme name

`CookieJWTSyncAuth` and `CookieJWTAsyncAuth` now default
`security_scheme_name` to `jwt_cookie` instead of `jwt`.
Previously it was the same as the `HeaderJWTSyncAuth`
and `HeaderJWTAsyncAuth` one, so using both in a single endpoint
generated a single `jwt` security scheme and requirement.

Regenerate OpenAPI snapshot tests. Find clients and tests that look up
the `jwt` security scheme for cookie auth and use `jwt_cookie`.
To keep the old name, pass `security_scheme_name='jwt'` explicitly.

### `OpenAPIConfig` rejects `openapi_version` below `3.1.0`

`OpenAPIConfig(openapi_version='3.0.3')` now raises `ValueError`.
OpenAPI `3.0.x` was never really supported: it predates JSON Schema,
which is what `pydantic` and `msgspec` generate.

Find every `OpenAPIConfig(...)` with an explicit `openapi_version`
below `3.1.0` and either remove the argument (the default is valid)
or set it to `3.1.0` or newer.

### OpenAPI generators take `metadata` and `controller_cls`

`SecuritySchemeGenerator.__call__` and `ResponseGenerator.__call__`

`ResponseSpec.get_schema` now accepts `controller_cls`
instead of `serializer`.

Find every subclass of these generators and every direct call

Before:
    spec.get_schema(serializer=MsgspecSerializer, ...)

After:
    spec.get_schema(controller_cls=MyController, ...)

### Schema generation entry points take `route_metadata` and `controller_cls`

- `ComponentParserGenerator.__call__` accepts `route_metadata`
  and `controller_cls` instead of `path` (the `URLPattern`)
  and `serializer`: `(operation_id, route_metadata, metadata, controller_cls)`.
- `OperationIdGenerator.__call__` accepts `controller_cls` instead
  of `suffix`: `(path, metadata, controller_cls)`.
  The suffix is produced by the new `generate_suffix` method.
- `ParameterGenerator.__call__` accepts `metadata` and `controller_cls`
  instead of `serializer` and `context`:
  `(model, model_meta, metadata, controller_cls, *, param_in)`.
- `Controller.get_schema` accepts `route_metadata` instead of `path`
  and `route`: `(route_metadata, context, router)`.
- `Endpoint.get_schema` accepts `route_metadata` instead of `path`
  and `route`: `(route_metadata, controller_cls, context, router)`.
- `Endpoint.get_operation_id` was removed. Customize the
  `OperationIdGenerator` instance in the OpenAPI config
  or pass `operation_id=` to `@modify` / `@validate` instead.

`route_metadata` is `dmr.openapi.collector.InternalRouteMetadata`,
with `path`, `is_regex`, `normalized_path`, `regex()`, and `converters()`.

Find every subclass of these generators, every override of `get_schema`
on controllers and endpoints, and every `get_operation_id` override
or call, and update them.

Before:
    class MyOperationIds(OperationIdGenerator):
        def __call__(
            self,
            path: str,
            suffix: str,
            metadata: EndpointMetadata,
            serializer: type[BaseSerializer],
        ) -> str: ...

After:
    class MyOperationIds(OperationIdGenerator):
        def __call__(
            self,
            path: str,
            metadata: EndpointMetadata,
            controller_cls: type[Controller[BaseSerializer]],
        ) -> str: ...

### Reworked how OpenAPI schema components are registered

`SchemaGenerator.__call__` lost `skip_registration`
and `register_referenced_components` parameters and returns `Schema`.
Use `SchemaGenerator.load` to get a schema with its components
kept locally (a `LoadedSchema` with `schema`, `defs`, `annotation`,
and `name`), and `SchemaGenerator.register(used, *loaded)` to register
only the components that the final result references.
Removed `SchemaRegistry.try_unregister` and the unused
`dmr.openapi.core.registry.SchemaCallback` protocol.
`ResponseGenerator.get_schema` accepts `content_schema`
to skip generating a schema from the return type,
`FileResponseSpec` uses it instead of removing `FileBody` afterwards.

Find every call of the schema generator with `skip_registration=`
or `register_referenced_components=`, every `try_unregister` call,
and every `SchemaCallback` import:

Before:
    schema = context.schema_generator(
        annotation, serializer, skip_registration=True,
    )
    ...  # build the final object from `schema`
    context.schema_generator(
        annotation, serializer, register_referenced_components=True,
    )

After:
    loaded = context.schema_generator.load(annotation, serializer)
    final = ...  # build the final object from `loaded.schema`
    context.schema_generator.register(final, loaded)

Custom response specs that generated a schema and then edited it
should pass the edited schema as `content_schema`
to `ResponseGenerator.get_schema`.

### `Reference` objects are not allowed in schema positions

OpenAPI `3.0` style `Reference` objects were removed from schema positions:
since OpenAPI 3.1 a `$ref` inside a schema is a JSON Schema keyword.
`SchemaRegistry.register` and `SchemaRegistry.get_reference` return
`Schema` with `ref` set, `SchemaRegistry.maybe_resolve_reference` accepts
only `Schema`, and schema-typed fields of OpenAPI objects
(`Schema.items`, `MediaType.schema`, `Parameter.schema`, and so on)
no longer accept `Reference`.
`Components.path_items` is typed as `dict[str, PathItem] | None`,
the spec does not allow `Reference` there either.

Find every `Reference(ref=...)` placed into a schema position
and every `isinstance(schema, Reference)` check in custom OpenAPI code:

Before:
    Reference(ref='#/components/schemas/User')

After:
    Schema(ref='#/components/schemas/User')

`Reference` is still valid for parameters, responses, headers,
and other non-schema components.

### Removed `OpenAPIContext.register_schema`

All custom schema override features are gone. Use the serializer-native
tools instead: `PydanticSchemaGenerator.json_schema_kwargs`
for `pydantic` and `MsgspecSchemaGenerator.schema_hook` for `msgspec`,
or `extra_json_schema` on the model itself.

Generated examples now land on the JSON Schema `examples` list instead of
the OAS `example` keyword. Examples written by hand are not rewritten.

Regenerate OpenAPI snapshot tests and update any code that reads

### OpenAPI object fields that accept `None` default to `EMPTY`

Fields where `None` is a real value now default to `EMPTY`
instead of `None`: `Schema.const`, `Schema.default`, `Schema.example`,
`Example.value`, `Example.data_value`, `Header.example`,
`MediaType.example`, `MediaTypeMetadata.example`,
`ParameterMetadata.example`, `Parameter.example`,
